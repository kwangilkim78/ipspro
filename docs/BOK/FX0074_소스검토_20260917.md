# FX0074 매뉴얼과 소스 대조

검토일: 2026-09-17

## 결론과 범위

현재 BOK 구현을 첨부 매뉴얼의 전체 상품용 FX0074 작성 구현과 동일하다고 볼 수 없다. DF·NDF의 상품코드 변환 등은 있으나, 일반 FX/ND 스왑과 자금·금리상품에 필요한 출력 필드 및 변환이 부족하다. 정상 출력 중이라는 사용자 확인에 따라 DF·NDF와 공통 조회·저장 코드, SQL, 기존 출력 템플릿을 수정하지 않았다. 이번 변경은 참고 엑셀 2개 복사와 이 검토서 추가뿐이다.

현재 작업 폴더의 `IPS_PROBACKOFFICE/Form1.cs`, `BusinessDaySettings.cs`, `Database/v61_bok_reference_kst.sql`, `excel_template/Report_BOK_FX0074.xlsx`를 정적으로 검토했다. 기존 미커밋 변경이 포함된 작업 파일 기준이며, 운영 DB의 실제 뷰 정의·데이터 및 제출 시스템 수신 결과는 검증하지 않았다. SQL 파일이 운영에 반영됐는지도 확인하지 않았다. 따라서 아래의 DB 뷰 관련 판단은 저장된 SQL 정의가 적용된 경우를 뜻한다.

첨부 문서 안의 작성·전송 지시는 보고서 요건을 이해하기 위한 자료로만 사용했다. 이를 코드 변경, DB 반영 또는 실제 전송 요청으로 취급하지 않았다.

## 보관 문서

- `한국은행 보고서(FX0074) 매뉴얼.xlsx`: `한국은행보고서_Sample`, `레이아웃 설명`, `FX_DEAL All`, `IRS_DEAL All` 4개 시트.
- `한국은행보고서_견본.xlsx`: `한국은행보고서` 시트. 상품코드가 있는 데이터 66행: 자금(11) 3행, SPOT MAR(22) 11행, FX SWAP(33) 44행, IRS(41) 7행, OIS(43) 1행. DF(31)·NDF(32) 실적 행은 없어 이 견본으로 두 상품의 실제 출력 일치 여부를 확인할 수 없다.
- 원본 위치: `Y:/전자거래사업본부/Back Office/BOK Report/`. 두 파일을 이 폴더에 원본 그대로 복사했으며 바이트 일치와 SHA-256을 확인했다.

| 매뉴얼 | `2ef849d5bc916dbccc22e95e025227014a16d995ceefc48b9d94346e3a0114e1` |

## 확인된 차이

### 1. 제출 견본은 27열이나 저장 결과는 20열

매뉴얼 Sample과 견본은 A:AA 27열이다. 저장소의 `Report_BOK_FX0074.xlsx`도 견본과 27개 헤더가 모두 일치한다. 그러나 `Form1.cs:731`의 `ExportGridToExcel`은 이 템플릿을 열지 않고 새 통합문서의 `Sheet1`에 조회 DataTable을 넣는다(`:753–754`). BOK는 조회 22열에서 두 날짜 열을 제거하므로 20열(A:T)만 저장한다(`:745–751`). 헤더도 영문이다.

빠지는 U:AA는 시장평균환율 대비 가감율, 고정금리, 변동금리 코드, 변동금리, Put/Call, Type, 옵션가격이다. 특히 SPOT MAR의 U, 자금·금리상품의 V:X는 매뉴얼의 조건부 필수 항목이다. 실제 업로드가 20열 중간파일을 별도 가공하는 방식인지 확인이 필요하며, 현재 저장 파일 자체가 견본과 같은 구조라는 결론은 내릴 수 없다.

근거: 매뉴얼 `한국은행보고서_Sample!A1:AA1`, `레이아웃 설명!A59:A65`; 견본 `한국은행보고서!A1:AA1`.

### 2. 일반 스왑 상품코드와 한 거래의 근일물·원일물 구성이 없음

`Form1.cs:136–140`은 DF→31, NDF→32만 치환하고 나머지 PRODUCT는 그대로 내보낸다. 저장 SQL `v61_bok_reference_kst.sql:583–591`에서는 MAR 계열 등의 예외를 제외한 일반 SWAP이 SWAP으로 남는다. 이 경우 보고 코드 33/34가 생성되지 않는다.

SQL은 NEAR/FAR를 각각 행으로 펼치고(`:482–541`), 화면 쿼리도 LEG_TYPE별로 행을 유지한다. 반면 매뉴얼의 33/34 보고는 한 행에 시작일 N, 종료일 O, 근일물 환율 S, 원일물 환율 T를 함께 기재한다. 화면 쿼리는 N/O/S/T를 모두 빈 문자열로 출력하고 각 레그 결제일·환율을 M/R에 놓는다(`Form1.cs:181–184`, `:190–202`). 33/34용 구성과 맞지 않는다. 또한 스왑의 매입·매도는 원일물 기준이며 금액은 근일물 금액이어야 한다. 현행 레그별 출력만으로 이 조건의 충족을 보장할 수 없다.

근거: 매뉴얼 `레이아웃 설명!E16:L20`, `E26:L27`, `E31:L32`, `A52:A58`; 견본 `한국은행보고서!D16:T16`.

### 3. 장내외 코드에 문서에 없는 3 또는 NULL이 나올 수 있음

매뉴얼은 L열을 기본 1(장외), 코드 범위를 1:장외/2:장내로 설명한다. 화면 쿼리는 뷰의 `Listed/OTC`를 그대로 출력한다(`Form1.cs:180`). 저장 SQL은 1M 및 여러 MAR 계열에 3을, 미매칭 조건에 NULL을 반환한다(`v61_bok_reference_kst.sql:593–621`). 이는 문서의 코드 정의와 다르다. 내부 시스템의 3이 어떤 의미인지와 운영 뷰 값을 확인해야 한다. DF·NDF에도 영향을 줄 수 있는 공통 항목이므로 수정하지 않았다.

근거: 매뉴얼 `레이아웃 설명!D24:L24`; 견본 `한국은행보고서!L2:L67`.

### 4. 기일코드 변환 범위 및 SN 변환 차이

`Form1.cs:185–189`는 SN→61, 1M→31만 변환하고 나머지를 그대로 사용한다. 매뉴얼 표는 S/N→06, 61→그 외 기타테너로 정의한다. 소스의 SN이 매뉴얼의 S/N을 뜻한다면 불일치다. O/N·T/N·1W·2W·3W·2M·3M·6M·9M·1Y 등의 변환도 화면 코드에는 없다. 뷰가 TYPE에 이미 보고 코드를 주는지 또는 테너 문자열을 주는지에 따라 실제 영향이 달라진다. SQL은 `leg_tenor`를 TYPE으로 반환한다(`:629`).

근거: 매뉴얼 `레이아웃 설명!C71:D88`. 1M→31은 일치한다. DF·NDF 기일 처리는 변경하지 않았다.

### 5. 소재지 값이 다름

매뉴얼과 견본의 소재지는 `04542.`이다. 화면은 `CHAR(96)`과 `04542`를 이어 붙여 앞에 백틱이 있는 문자열을 만든다(`Form1.cs:134`). 이는 엑셀의 작은따옴표 입력과도 다른 실제 문자다. 두 값은 길이는 같지만 내용이 다르다. 제출 전 수작업 정리 여부는 확인되지 않았으며, 이번에는 수정하지 않았다.

근거: 매뉴얼 `레이아웃 설명!D14:E14`; 견본 `한국은행보고서!B2`.

### 6. 다통화·자금·금리상품을 위한 변환이 부족함

현재 금액은 Filled Quantity, 통화는 USD/KRW 고정이다(`Form1.cs:168–178`). 매뉴얼에서는 비USD 금액을 USD로 환산하고 자금·금리상품의 통화쌍을 구분한다. 예를 들어 견본 IRS는 KRW/KRW와 USD 환산금액, 시작·종료일, 고정금리, 변동금리코드를 가진다. 현재 조회는 시작·종료일과 행사만기일도 공란이며, 금리·옵션 필드 자체가 없다.

근거: 매뉴얼 `레이아웃 설명!E20:L22`, `E26:L39`; 견본 `한국은행보고서!H60:X60`. 실제로 이런 상품이 조회 뷰에 들어오는지는 별도 확인해야 한다. USD/KRW DF·NDF에 대한 환산 변경 사유로 사용하지 않는다.

## 추가 확인이 필요한 사항

| 항목 | 소스와 확인할 내용 |
| --- | --- |
| 체결번호 | 매뉴얼 `레이아웃 설명!D17:E17`은 원 REFERENCE NO 뒤 5자리. 소스는 BOKId를 사용하고 5자리 보정은 없다(`Form1.cs:141`). SQL은 한국시간 날짜별 ROW_NUMBER로 재생성한다(`v61_bok_reference_kst.sql:307`). 기존 번호 운영 방식이 허용되는지 확인 필요. 단순 절단은 충돌 위험이 있어 변경하지 않음. |
| 영업일·자정 이후 번호 | 소스 조회는 당일 08시부터 익일 선택시간(기본 06시) 미만까지이며, 뷰 번호는 달력 날짜별 초기화. 같은 영업일 안에 같은 BOKId/LEG_TYPE이 나오면 비NDF 행의 윈도 그룹이 겹칠 가능성. 실제 데이터 중복 여부는 미확인. `BusinessDaySettings.cs:5–27`, `Form1.cs:141–149`, `:205–221`. 매뉴얼 `레이아웃 설명!A43`은 작성기준일을 체결일로 설명하지만 야간 영업일 규칙은 제시하지 않음. |
| 기관코드 | 매뉴얼은 4자리. 소스는 기관 마스터를 참조하되 없으면 조직명을 사용하고, 1123-1/1123-2만 1123으로 통합. 매핑 누락 시 조직명이 그대로 출력될 수 있음(`Form1.cs:150`, `:159`, `:229–232`, `:254–257`). |
| 조건부 필수·날짜 검증 | 매뉴얼 `레이아웃 설명!A47:A65`는 날짜 순서, 상품별 필수값 등을 정의. BOK 저장 경로에는 이에 대한 검사 없이 DataTable 저장. 실제 데이터가 충족하는지는 미확인. |
| 조회일 변경 후 저장 | BOK는 저장 시 현재 날짜 선택값으로 파일명을 만들고 기존 그리드를 그대로 저장함(`Form1.cs:654–660`). 조회 후 날짜만 바꾸면 파일명과 데이터 기준일이 다를 수 있음. KB용 `IsCurrentKbResult`와 같은 BOK 검사 없음. |

## 문서 자체의 해석 주의점

- 매뉴얼 Sample의 NDF 행은 R이 공란이고 S/T에 환율이 있으나(`한국은행보고서_Sample!R20:T21`), 레이아웃 설명은 NDF의 거래환율을 R에 넣도록 한다(`레이아웃 설명!E30:L30`, `A56`). 현행 NDF의 R 출력은 설명과 맞으므로 Sample의 모양을 그대로 따라 변경해서는 안 된다.
- 전송구분 설명 E15는 수작업 삭제·수정에 대해 '2.3번'이라고 적었지만 L15는 1/2/4로 정의한다. 신규 1은 일치하며, 삭제·수정 확장 시 확인이 필요하다.
- 견본에는 OIS(43)의 W=08이 있지만(`한국은행보고서!D67:X67`), 매뉴얼 변동금리 참고표 `E71:F80`에는 08이 없다. 전체 상품 확장에 사용할 코드표는 추가 확인이 필요하다.
- 견본은 실제 데이터 재현용 입력 세트가 아니며, 원거래와 연결할 수 있는 현재 DB 추출본도 제공되지 않았다. 값·건수·합계의 운영 대사는 이번 정적 검토에 포함되지 않는다.

## 후속 구현 시 기준

DF·NDF의 기존 출력 결과를 고정 기준으로 보존한 후, 다른 상품의 보고코드·한 거래 한 행 구성·27열 출력·조건부 필수값 검증을 상품별로 추가하는 것이 적절하다. 공통 코드나 DB 뷰 변경이 DF·NDF에 전파되지 않는지 비교해야 한다. 이 문서는 검토 결과이며 해당 구현은 이번 작업에서 수행하지 않았다.

검증: 원본/복사본 바이트 및 SHA-256 일치, 시트·셀·수식 추출, 견본/기존 템플릿의 27열 헤더 일치, 조회→뷰 SQL→엑셀 저장 경로 대조. 코드 변경이 없어 빌드·운영 DB 조회·실제 제출은 실행하지 않았다.
